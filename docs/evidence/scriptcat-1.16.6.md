## Scope

No delivery semantics were changed: markers, role profiles, prompt budgets, statuses,
Notion and Drive contracts and the embedded regulation digest stay as they were. The
release fixes the one thing the incident actually asked for: an acceptance-queue row
must reach its addressee, always, without waiting for a prompt that never comes.

- `24-feedback.refreshQuestions` no longer excludes a row forever by the
  `cfn-q-handoff:<id>` mark. `handWaitingRow` writes that mark before delivery is
  confirmed, while `dropAnswer` empties the answer queue and the phantom sweep clears
  the expectation slot — the row stayed with no running trace and no retry.
  "Handed over" is now checked against the live trace of four records
  (`answerHandoffLive`: answer queue, `cfn-expect` answer/answer-return, unposted
  `cfn-pending` turn, answer-return receipt). A mark older than `C.questionCheckMs`
  with no live trace means the row is re-handed (`handoffNeedsRequeue`).
- Retries are counted (`cfn-q-rehandoff:<id>`, limit `C.answerRehandoffMax` = 2). Past
  the limit the row is not "queue will wait" any more but a lost delivery: pause kind
  `answer-orphan`, classified `transport` → `maintainer`, `healHoldsCycle` false, so
  the cycle keeps running while Transport Maintainer gets the defect. The counter is
  reset when the row is closed by an answer, so the next incident starts from zero.
- The addressee survives the queue and the base read regardless of `gate`
  (`queueAnswer`, `questionFromRow`): `gate` decides whether the turn is held, not who
  answers. D-083 strictness stays where it belonged — `parseQuestion` still zeroes
  `need` for a marker question without `gate`, and `questionProps` still writes the
  addressee label only for a gated question.
- `27-review-answers.startAnswer` holds the queue head only for a gated question. An
  ordinary row addressed to a role that is not ready is answered by acceptance and the
  substitution is named in the journal (`answer-need-fallback`), instead of returning
  `false` and stalling every row behind it (`answerPending()` is one head for the whole
  queue).
- A long wait for the single expectation slot is now visible: `noteAnswerStarved`
  (`answer-starved`) reports the waiting minutes, the role holding the slot and the
  row still queued, called from the cycle step in `28-cycle.js`.
- Both `@version` and the runtime `SCRIPT_VERSION` fallback moved to `1.16.6`
  together, as the version contract requires (D-027).

## Probe on shipped code

`tools/script-cat/tests/relay-answer-orphan-smoke.mjs` cuts the real blocks out of the
built `relay.user.js` (not from `src/`) and runs them:

- `handoffNeedsRequeue`/`answerHandoffLive` executed over a synthetic store: no mark →
  hand off; fresh mark → wait; stale mark with the row in the answer queue → wait;
  stale mark with an `answer` or `answer-return` expectation → wait; stale mark with an
  unposted `cfn-pending` turn → wait; answer-return receipt → wait; a `dispatch`
  expectation for another card, and a stale mark with no trace at all → re-hand.
- the retry counter grows and resets (`bumpAnswerRehandoff`/`resetAnswerRehandoff`), so
  the ceiling is per incident rather than per row forever;
- pause routing taken from the bundle table: `answer-orphan` → class `transport`, route
  `maintainer`, `with` not `warden`, `healHoldsCycle` false; `decideHeal` gives
  `maintainer` (1 of 2) and stops to the Master at the ceiling;
- `questionFromRow`, `queueAnswer` and the `startAnswer` branch are checked in the
  shipped text for the addressee rules above.

Red on the shipped 1.16.5 code and green on 1.16.6 was verified directly: the repository
tree at `HEAD` (`1.16.5` bundle and sources) with this probe fails on
«WOTR-сборка 1.16.6 объявлена», and with the version pin removed it fails one assertion
later on «adoption сверяется с живой передачей, а не с одной отметкой».

Five existing expectations moved with the release because they pinned the behaviour this
decision corrects, and each now names the reason in the test text:
`relay-adr-handoff-smoke` (lifetime handoff exclusion), `relay-direct-answer-smoke`
(`need` dropped without `gate`; the gated case still holds and still refuses to hand the
turn to another role), `docs-smoke` (same rule at source level, plus the fallback and
starvation notes), `relay-send-unregistered-smoke` (bundle version), and
`dispatch-coordinator-smoke` (suite count 123 → 124 with the new probe).
`regression-tests/relay-adr-default-integration.mjs` gained the new free names
(`handoffNeedsRequeue`, `bumpAnswerRehandoff`, `pause`, `logThrottled`) in its
`new Function` sandbox: it executes the real `refreshQuestions` block, so the block's
free identifiers have to be passed in — that is the established convention of that file.

## Release boundary

This evidence accepts the deterministic repository artifact and the bounded local gates
only. It does not claim browser installation or live dispatch: installing `relay.user.js`
in ScriptCat remains a manual owner action after comparing SHA-256 with this record
(D-027).

Two facts visible in Notion belong to the Master and to acceptance, not to this release:

- the open row `41f6f0cf-…-c69c24308819` stays «Ждёт» with an empty «Ответ». After this
  build it is handed over, retried within the ceiling and — past the ceiling — escalated
  to the Transport Maintainer by name; the row is not edited by hand and not closed here;
- the cycle step order is unchanged on purpose: the answer queue still does not overtake
  a live turn, because the expectation slot is one for all roles. What changed is that a
  long wait is now reported instead of being silent.
