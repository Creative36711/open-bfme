# Сборка бандла ScriptCat этим репозиторием

Решение — `docs/DECISIONS.md`, запись `WOTR-D-033`; правило — §1 и §15 `docs/REGULATION.md` (с версии 1.5).

Транспорт (`Creative36711/relay-wotr`) — одна библиотека на много проектов. Он не хранит наших
документов, не читает наше дерево и не подстраивается под проект. Бандл, который получают агенты,
собираем мы: `tools/relay/build.mjs` скачивает запиненный выпуск транспорта, кладёт в развернутый
снимок **наши** `docs/regulation-digest.md` и `docs/REGULATION.md` (их сборка сама ищет `docs/`
вверх от комплекта — это единственный вход, который мы подставляем), запускает **его** `build.mjs`
и **его** узел проверок `tools/relay-build.mjs`, и проверяет результат по sha256. Правка регламента
не создаёт задач в транспорте и не требует синхрон-PR туда.

## Файлы

| Путь | Что хранит |
|---|---|
| `pin.json` | запиненный выпуск: репозиторий, коммит (или тег), `@version`, `contractVersion`, sha256 архива снимка, sha256 артефакта и номер регламента в нём, пути входов и артефактов |
| `build.mjs` | узел сборки: скачивание → сверка хешей → подстановка docs → сборка → проверки → `build/relay/` |
| `project-profile.json` | профиль проекта для транспорта; байт-в-байте копия их `tools/script-cat/wotr-project.json`, чтобы шаг 2 перенёс файл, а не переписал значения |
| `deploy.json` | наш деплой: целевой Apps Script и назначение артефакта. Только здесь, только наше |
| `relay_test.mjs` | тесты узла (`node --test tools/relay/relay_test.mjs`), герметичные: сеть подменяется, кэш — временный каталог |

Артефакты — в `build/relay/`: `relay.user.js`, `prompt-coverage.json`, `build-manifest.json`
(без меток времени: два запуска обязаны давать байт-в-байт одинаковые файлы, иначе сверять
установленный бандл нечем).

## Команды

```bash
node tools/relay/build.mjs              # собрать и допустить (или отказать)
node tools/relay/build.mjs --check      # два запуска, сверка байтов: детерминизм
node tools/relay/build.mjs --verify     # проверить собранный артефакт без сети
node tools/relay/build.mjs --json       # машинный отчёт в stdout
node tools/relay/build.mjs --offline    # только из кэша (нет кэша — код 3)
node --test tools/relay/relay_test.mjs  # тесты узла
```

Коды возврата как у узла транспорта: `0` — допущено, `1` — неверный запуск или негодный пин,
`2` — проверка не пройдена (сборка не допущена), `3` — источники или входы не получены. Отказ
всегда объясняет причину; ни одна проверка не превращается в `pass`, если её не удалось выполнить.

Что именно считается достаточным основанием отказа: sha256 снимка ≠ запиненный; в снимке нет
`tools/script-cat/build.mjs` или `tools/relay-build.mjs`; узел транспорта вернул отчёт без списка
проверок или не допустил сборку; вшитый в бандл регламент ≠ наш `docs/regulation-digest.md`; номер
во вшитом регламенте ≠ шапка `docs/REGULATION.md`; `@version` ≠ запиненный; наши docs совпадают с
текстами снимка, но бандл не равен запиненному артефакту (значит наша сборка воспроизводит транспорт
иначе, чем он сам); наши docs отличаются, а бандл совпал с запиненным (значит регламент в бандле
чужой, из выпуска транспорта).

## После выпуска транспорта (перепин)

```bash
git -C <клон relay-wotr> rev-parse main                      # коммит, который принимаем
node tools/relay/build.mjs                                    # соберёт и покажет расхождение
```

`pin.json` обновляется четырьмя полями: `transport.commit`, `snapshot.sha256` (берётся из
скачанного архива; `build.mjs` печатает ожидаемое и фактическое значение в причине отказа),
`userscriptVersion` из `@version` принятого выпуска и `artifact.sha256` с
`artifact.regulationVersion` (sha256 их `tools/script-cat/relay.user.js` на этом коммите).
`contractVersion` — `protocolVersion` из `tools/script-cat/contracts/agent-protocol.json`.
Перепин — обычный PR с гейтом `build: full`: бандл, собранный нами, обязан пройти `--check`.

## Деплой

Принятый `build/relay/relay.user.js` вставляется в проект Apps Script `deploy.json.target`
(`wotr-remaster-relay`), публикуется версия, соответствующая `@version` бандла; userscript в
браузер устанавливает человек. `build-manifest.json` — то, что прикладывается к evidence: по нему
видно, какой выпуск транспорта, какие байты docs и какой отпечаток сборки попали в установку.

## Границы

- Мы не правим дерево транспорта: только читаем запиненный снимок и подаём ему свои входы.
- Транспорт не читает наш репозиторий: обратных ссылок (`open-bfme`, `WOTR-*`, наши Notion/Drive ID)
  в его сборке быть не должно — это проверяет их `portability-guard` (шаг 2).
- Кэш снимка живёт вне рабочего дерева (по умолчанию `$TMPDIR/wotr-relay-cache`): узел транспорта
  определяет проверяемое дерево по `git status`, и кэш внутри репозитория заставил бы его проверять
  наше дерево и отказывать. Проверка вшита в `assertCacheOutsideRepo`, а не оставлена на удачу.
- `@version` бандла при нашей правке docs не меняется и не должен: он говорит о выпуске транспорта.
  Идентичность сборки проекта — `artifact.bundleSha256` в манифесте.

## Что изменит шаг 2 (`TRANS · NEU-1`)

Когда транспорт примет digest и профиль как входы сборки (`--digest`, `--profile`) и удалит своё
зеркало наших docs, `build.mjs` переключится с подстановки файлов в `docs/` снимка на явную передачу
параметров, а `pin.json` начнёт указывать на `kind: "release"`. Схема пина это уже допускает; пока
релизов у транспорта нет (ни release, ни tag), поэтому пин — по коммиту. До закрытия шага 2 зеркало,
вшитый digest и их `verify:scriptcat` остаются рабочими: состояния «агенты без регламента» нет ни in
одном шаге.
